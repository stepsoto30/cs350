Summarize the project and what problem it was solving.

SysTec wanted to enter the global thermostat market and was seeking the development of a thermostat that could send data to SysTec's server software over Wi-Fi. The project required the creation of a working prototype that demonstrated low-level thermostat functionality. Through the use of a Raspberry Pi, buttons, LEDs, and an LCD display, the project simulated the basic features of a smart thermostat while providing experience with embedded systems development.

What did you do particularly well?

I did well in developing a deeper understanding of how to create a low-level thermostat system. Each week's assignment involved adding new hardware functionality, which gave me the opportunity to fully understand how each component worked within the system. Additionally, reviewing and modifying the provided code helped me understand how software communicates with hardware through the Raspberry Pi. This hands-on approach allowed me to build confidence in both hardware integration and software development.

Where could you improve?

I could improve by incorporating solutions for potential real-world malfunctions. For example, hardware could experience delays due to Wi-Fi connectivity issues, or buttons could lose functionality if they become stuck or damaged. Designing and testing error-handling mechanisms for these situations would make the thermostat more reliable and closer to a production-ready system.

What tools and/or resources are you adding to your support network?

The tools and resources I am adding to my support network include Raspberry Pi, GPIO, and troubleshooting hardware integration. I also plan to continue using lab guides and visual references because they helped me better understand how components should be assembled and connected. These resources will be valuable for future embedded systems and hardware-based projects.

What skills from this project will be particularly transferable to other projects and/or coursework?

One skill that will be particularly transferable is breaking a project down into smaller, manageable tasks. This approach allowed me to develop and test the code in stages while ensuring the hardware was functioning correctly. I also gained experience troubleshooting hardware and software issues, which is a valuable skill for future projects. Additionally, using the lab guide's visual references helped me better understand hardware layouts and assembly processes.

How did you make this project maintainable, readable, and adaptable?

I made this project maintainable, readable, and adaptable by organizing the code into functions that responded to user input from the buttons. As I added new functionality, I kept the code as simple as possible and avoided hard-coding values whenever possible. This made it easier to modify or expand the program without affecting existing functionality or causing the system to crash. By keeping the code modular and flexible, future updates can be implemented more efficiently.
